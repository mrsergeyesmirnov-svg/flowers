# Безопасность Flowers

## Секреты

- Токены Telegram, платёжные ключи и идентификаторы администраторов хранятся только в Railway Variables.
- Секреты запрещено добавлять в Git, `ADMIN_SHOPS_JSON`, клиентский JavaScript, URL и логи.
- Панели показывают только публичный `@username` бота. Telegram ID пользователей и администраторов маскируются.
- При подозрении на утечку токен бота отзывается через BotFather и заменяется в Railway.

## Доступ

- Super Admin и админ магазина авторизуются только через проверенную Telegram `initData`, а не через переданный из браузера ID или пароль.
- Кнопка админки показывается ботом только разрешённым Telegram ID; обычный пользователь её не видит.
- Все серверные операции проверяют роль и `shop_id`; значение `shop_id` от клиента не считается доверенным.
- Журнал действий фиксирует входы, изменение цен, наличия, заказов, согласий и запуск рассылок без записи секретов.

## Персональные данные и согласия

Согласия независимы и хранятся как неизменяемые события:

- `data_processing` — обработка данных для подбора и заказа;
- `florist_contact` — связь по конкретной заявке;
- `marketing` — рекламные рассылки.

Для каждого события сохраняются `shop_id`, внутренний `customer_id`, тип, действие `granted/revoked`, время, версия политики и источник. Telegram `chat_id`, необходимый для отправки, шифруется на сервере и не показывается в панели.

Отзыв рекламного согласия не отключает сервисные сообщения по активному заказу. Рассылка выбирает только клиентов с последним действующим событием `marketing=granted`.

## Рассылки

До отправки сервер повторно проверяет согласие каждого получателя. Для кампании сохраняются:

- размер подходящей аудитории;
- успешно принятые Telegram сообщения;
- ошибки и отписки;
- автор, время запуска и текст кампании.

Telegram Bot API не даёт достоверного статуса прочтения, поэтому панель не должна называть успешную отправку «прочитано» или «доставлено человеку».

## Админ магазина — следующий этап

- ассортимент, фотографии и состав;
- цена и актуальное наличие;
- заявки и статусы заказов;
- роли владельца и менеджера;
- база клиентов с маскированными идентификаторами;
- рассылки только по согласованной аудитории;
- счётчики `подготовлено / принято Telegram / ошибка / отписка`;
- экспорт и удаление данных по запросу пользователя.

## Перед промышленным запуском

Нужны Postgres с резервными копиями, шифрование чувствительных полей с ротацией ключей, проверка Telegram `initData`, webhook с секретным путём, аудит зависимостей, мониторинг ошибок и финальная юридическая проверка политики под реквизиты конкретного магазина.
