# Цветы — персональный флорист

Мобильное демо сервиса, который подбирает три букета по описанию человека, поводу и бюджету, а затем предлагает релевантные дополнения к заказу.

## Запуск

```bash
npm run dev
```

Откройте `http://localhost:4173`. Зависимости устанавливать не нужно.

## Проверка логики подбора

```bash
npm test
```

Это демонстрационный MVP: каталог хранится в `recommender.js`, заявка и оплата пока не отправляются.

## Super Admin

Админка открывается только из Telegram-бота. Сервер проверяет подпись Telegram `initData`, затем назначает роль по ID из Railway Variables:

```env
SUPERADMIN_TELEGRAM_ID=ваш_telegram_id
SHOP_ADMIN_TELEGRAM_IDS=id_владельца,id_менеджера
SHOP_ID=romashka
PRIVACY_OPERATOR=ИП Иванова Анна Сергеевна
PRIVACY_INN=000000000000
PRIVACY_OGRN=000000000000000
PRIVACY_ADDRESS=г. Санкт-Петербург, ...
PRIVACY_EMAIL=privacy@example.ru
PRIVACY_PHONE=+7 ...
PRIVACY_RKN_ID=номер записи в реестре операторов
PRIVACY_HOSTING_LOCATION=Российская Федерация, город и провайдер
SHOP_OPERATOR=ИП и наименование магазина
```

До приёма реальных заявок заполните все реквизиты. Если база Railway физически находится не в России, одной политики недостаточно: для первичной базы персональных данных граждан РФ требуется российская локализация, а для допустимой трансграничной передачи — отдельная процедура и уведомление Роскомнадзора.

Обычные пользователи не видят кнопку админки. Super Admin видит все настроенные магазины; владелец и менеджеры — только свой магазин. Прямой запрос к API без действительной подписи Telegram получает отказ.

Узнать собственный ID без сторонних сервисов можно командой `/myid` в личном чате с ботом.

Для нескольких тестовых магазинов можно передать конфигурацию JSON:

```env
ADMIN_SHOPS_JSON=[{"id":"romashka","name":"Ромашка","bot":"@romashka_bot","plan":"Start","subscription":"active","monthly":4900,"paidUntil":"2026-10-21","botStatus":"online","orders":12}]
```

Допустимые статусы подписки: `trial`, `active`, `overdue`, `paused`; бота: `online`, `setup`, `error`.

Не добавляйте в `ADMIN_SHOPS_JSON` токены ботов, платёжные ключи или Telegram ID. Требования к хранению секретов, согласиям и будущим рассылкам описаны в [`SECURITY.md`](./SECURITY.md).

### Рабочее управление магазинами

Добавьте один общий PostgreSQL в проект Railway и передайте всем сервисам магазинов созданную Railway переменную `DATABASE_URL`. При первом запуске таблицы создадутся автоматически, а ассортимент пилотного магазина загрузится из демо-каталога. У каждого сервиса остаются собственные `TELEGRAM_BOT_TOKEN`, `SHOP_ID` и `SHOP_ADMIN_TELEGRAM_IDS`, но магазины и ассортимент управляются через общую базу.

Super Admin может подключать и приостанавливать магазины, менять тариф, статус и дату оплаты, добавлять букеты, редактировать цену, состав, фотографию и наличие. Администратор магазина видит и редактирует только ассортимент магазина из `SHOP_ID`.
